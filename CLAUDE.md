# LeaseWiz — working notes

An Australian novated lease explainer and calculator. Read `README.md` first for the
stack, setup and how the engine is put together; this file covers the conventions that
aren't obvious from the code.

## Ground rules

- **No hard-coded rates.** Anything that could change with a budget, an indexation or a
  ruling belongs in `lib/au/config.ts`, with a descriptor in `lib/au/params.ts` and a
  source in `lib/au/sources.ts`. Pages read it from `getActiveConfig()`. If you find
  yourself typing `0.47` or `$91,387` into a component, stop.
- **The engine is pure.** `lib/au/novated.ts` and `lib/au/tax.ts` take inputs plus a
  config and return a result. No I/O, no React, no `Date.now()`. That is what makes
  them testable and what lets a saved scenario re-run against today's rules.
- **Store inputs, never results.** A saved scenario (`plans.data`, shaped by
  `lib/au/types.ts`) holds only what the user typed. Recomputing on read means a rate
  change updates every saved scenario for free.
- **Measure tax, don't assume it.** Never multiply by a headline marginal rate. Use
  `marginalRelief`, which computes the whole tax position twice and takes the
  difference — the only way bracket crossings, the LITO taper, the Medicare shade-in
  and HELP steps come out right.

## Design system

Tokens live in one `@theme` block at the top of `app/globals.css`, following the
Atlassian Design System ramp. Use the semantic names, never a raw Tailwind palette
colour:

| Use | Class |
| --- | --- |
| Primary text | `text-ink` |
| Secondary / body | `text-subtle` |
| Labels, captions | `text-muted` |
| Card surface | `bg-panel` + `border-line` + `shadow-[var(--shadow-card)]` |
| Sunken / subtle fill | `bg-panel-2` |
| Brand actions | `bg-accent text-white hover:bg-accent-soft` |
| Selected / tinted | `bg-accent-subtle text-accent border-accent` |
| Good / saving | `text-success-text`, `bg-success-subtle` |
| Caution | `text-warning-text`, `bg-warning-subtle` |
| Problem | `text-danger-text`, `bg-danger-subtle` |

`bg-emerald-500`, `text-slate-300` and friends will look wrong and will not survive a
theme change. Modal scrims are `bg-[#091e42]/54` (the ADS blanket).

## Conventions worth knowing

- **Copy.** Australian English, plain language, second person. State the mechanism,
  then the number. No exclamation marks, no emoji in product copy, no "amazing
  savings". The whole point of this app is that it isn't selling a lease — the tone has
  to earn that. Where a number is uncomfortable (the residual, a reportable fringe
  benefit) say so plainly.
- **Warnings** are generated by the engine (`LeaseResult.warnings`) and rendered
  verbatim, so the same caveat reaches the calculator, the report and the share link
  without being written three times.
- **Money** goes through `fmtCurrency` / `fmtCompact` from `lib/au/format.ts`. Always
  `tabular-nums` on a figure that sits in a column.
- **Server actions** live in `app/actions/`, return `{ ok }` or `{ error }` rather than
  throwing, and re-check authorisation themselves (`getCurrentUser` / `getAdmin`) —
  never trust the caller.
- **Tracking must never break a page.** `trackVisit` and `logVisitorEvent` swallow their
  own errors; keep it that way.

## Testing

- `npm test` for the suite; `npm run test:record` to also write results to the DB for
  `/admin/tests`. The top-level `describe()` title becomes the "area" shown there, so
  name it after the business area ("Fringe benefits tax", not "novated.ts").
- New engine behaviour needs a test that would fail without it. Prefer a test that
  asserts a *relationship* ("an exempt EV costs less than the same-priced petrol car")
  over one that pins a magic number — the magic numbers move every financial year.
- `tests/reference-data.test.ts` guards the config/params/sources contract. If you add
  a parameter, it will tell you what you forgot.
- `tests/sitemap.test.ts` forces a decision on every new public page: list it in
  `app/sitemap.ts` or add it to `EXCLUDED` with a reason.

## Database

`lib/migrations.ts` is the single source of truth for the schema — one `SCHEMA_SQL`
string plus idempotent seed functions. Every statement must be safe to run repeatedly
(`create table if not exists`, `alter table … add column if not exists`), because it
runs on every deploy. There is no migration-file chain to reason about; add to the
bottom and make it re-runnable.

## Things to be careful with

- **Reportable fringe benefits.** They belong on the packaged side of a before/after
  comparison only. See the note in `README.md` — this was a real bug once.
- **`Infinity` doesn't survive JSON.** The top tax bracket and HELP band round-trip
  through Postgres as `null`; `reviveConfig` restores them. Always load a stored config
  through `reviveConfig`, never raw.
- **The share token is a capability.** Anyone with the link can read the scenario.
  Private notes are deliberately excluded from the share query — keep them out.
